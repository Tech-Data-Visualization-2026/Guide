  • Path.cwd()는 data/와 output/ 같은 상대 경로가 어느 폴더를 기준으로 해석되는지 보여 줍니다.

15 · CREATE

값·빈 표·규칙값으로 배열을 만들고 모양을 확인합니다.

학습 대상 · 기존 값, 0으로 채운 표, 연속된 값의 표를 만들고 shape=(2, 3)을 읽습니다.

  • array는 이미 있는 측정값을 배열로 만듭니다.
  • zeros((2, 3))는 2행 3열의 빈 표를 만듭니다.

ARRAY CREATION
import numpy as np

reserved = np.array([2, 4, 3])
empty_table = np.zeros((2, 3), dtype=int)
slot = np.arange(6).reshape(2, 3)

print(empty_table.shape)  # (2, 3)
print(slot)
OUTPUT
empty_table = [[0 0 0]
               [0 0 0]]

17 · SELECT

인덱싱은 한 위치, 슬라이싱은 구간을 선택합니다.

m[1, 2]

두 번째 행, 세 번째 열의 값 5

m[:, 1:]

모든 행의 두 번째 열 이후

SELECT
m = np.arange(6).reshape(2, 3)
print(m)
# [[0 1 2]
#  [3 4 5]]

one = m[1, 2]
print(one)       # 5

part = m[:, 1:]
print(part)
# [[1 2]
#  [4 5]]

왼쪽 설명과의 연결: m은 2행 3열이므로 인덱스 1은 두 번째 행 [3, 4, 5], 인덱스 2는 그 행의 세 번째 값 5를 고릅니다. :는 모든 행, 1:은 두 번째 열부터 끝까지이므로 part에는 두 행의 [1, 2], [4, 5]가 남습니다.

슬라이싱 표기: start : stop : step

18 · NEW AXIS

새 축을 어디에 넣느냐에 따라 같은 값이 한 행 또는 한 열이 됩니다.

학습 대상 · 값 [10, 20, 30]은 바꾸지 않고, 행의 shape=(1, 3)과 열의 shape=(3, 1)을 구분합니다.

원본 · 1차원

102030

[10 20 30]
shape = (3,)

앞에 축 추가 · 한 행

102030

[[10 20 30]]
shape = (1, 3)

뒤에 축 추가 · 한 열

102030

[[10], [20], [30]]
shape = (3, 1)

핵심 확인

세 경우 모두 값은 10, 20, 30으로 같고 원소 수도 3개다. 달라지는 것은 값을 배치하는 축의 개수와 위치뿐이다. 따라서 한 행은 (1, 3), 한 열은 (3, 1)로 읽는다.

세 값은 그대로이고, 새 축이 들어간 위치만 shape를 바꿉니다.
視 데이터시각화View vs Copy

19 · MEMORY

두 배열이 같은 데이터 버퍼를 보는지가 핵심입니다.

View · 공유

새 배열 객체가 원본 데이터 버퍼를 공유합니다.

원본 ─ slice → View
View 수정 ─────→ 원본 변경

Copy · 독립

새 데이터 버퍼에 값을 복제합니다.

원본 ─ copy → Copy
Copy 수정 ─────→ 원본 유지
기본 슬라이싱은 View, .copy()는 Copy를 만듭니다.

視 데이터시각화Memory Test
VIEW_COPY_TEST.PY
import numpy as np

original = np.array([10, 20, 30, 40])
view = original[1:3]
copied = original[1:3].copy()

view[0] = 999
copied[0] = 999

assert original.tolist() == [10, 999, 30, 40]  # 통과
assert np.shares_memory(original, view)         # 통과
assert not np.shares_memory(original, copied)   # 통과

21 · PROVE

세 assert는 모두 통과하며, 통과하면 별도 출력이 없습니다.

1 · 원본 값 검증

결과: 통과. 기본 슬라이싱으로 만든 view가 원본과 값을 공유하므로 view[0] = 999가 원본의 두 번째 값도 999로 바꿉니다.

2 · View 공유 검증

결과: 통과. original[1:3]는 기본 슬라이싱이어서 새 값 저장소가 아니라 원본 데이터 버퍼를 함께 봅니다.

3 · Copy 독립 검증

결과: 통과. .copy()는 새 데이터 버퍼를 만들므로 copied[0] = 999를 해도 original은 더 바뀌지 않습니다.

값과 공유 여부를 함께 검증합니다.
