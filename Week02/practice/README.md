# 2주차 실습 — 불완전한 대용량 센서 배열 처리

## 목표

AI를 사용해도 된다. 다만 AI가 만든 최초 코드와 최종 코드를 함께 남기고, 배열의 실제 출력과 메모리 공유 여부를 직접 확인한다.

주어진 온도 측정값을 `공간 × 시간` 배열로 구성하고, 완전하지 않은 입력을 어떻게 처리할지 결정한다. 하나의 정답을 찾는 것이 아니라 **메모리를 적게 사용하는 방법**과 **누락된 입력을 견디는 방법** 사이의 선택을 실행 결과로 설명하는 것이 목표다.

## 데이터

- `data/temperature_complete.csv`: 1,000개 공간에서 24시간 동안 얻은 측정값 24,000개
- `data/temperature_missing.csv`: 마지막 공간의 7개 측정값이 누락된 측정값 23,993개
- 값의 단위는 섭씨온도의 10배인 정수다. 예를 들어 `215`는 `21.5°C`다.
- 첫 행은 열 이름 `temperature_tenths_c`이며, 그 아래부터 한 줄에 측정값 하나가 시간 순서대로 기록되어 있다.

완전 데이터는 `(1000, 24)`로 바꿀 수 있지만 누락 데이터는 원소 수가 24의 배수가 아니므로 그대로는 같은 모양으로 바꿀 수 없다.

## 필수 작업

1. 완전 데이터를 NumPy 배열로 읽고 `dtype`, `ndim`, `shape`, `size`를 출력한다.
2. 배열을 `(1000, 24)`로 바꾸고 한 값 선택, 한 행 선택, 여러 행·열 슬라이싱을 각각 실행한다.
3. `np.arange(1000)`으로 공간 번호를 만들고 `[:, np.newaxis]`를 적용해 `(1000, 1)` 모양을 확인한다.
4. 슬라이싱으로 만든 View와 그 View의 Copy를 각각 수정한 뒤 원본 변화와 `np.shares_memory` 결과를 출력한다.
5. 위 결과 중 원소 수, 모양, 선택한 값, View·Copy의 원본 변경 여부를 `assert`로 검증한다.

## 효율성 고찰

같은 완전 데이터를 최소 두 가지 `dtype`으로 만들어 `itemsize`와 `nbytes`를 비교한다. 최종 `dtype`을 하나 선택하고, 읽기만 할 부분에는 View를 쓰고 독립적으로 수정할 부분에만 Copy를 쓰도록 코드를 구성한다.

`README.md`에는 다음 내용을 남긴다.

- 비교한 `dtype`별 `itemsize`와 `nbytes`
- View로 둔 부분과 Copy로 만든 부분
- 더 적은 메모리만을 기준으로 고르지 않고 최종 방식을 선택한 이유

## 내결함성 고찰

누락 데이터 23,993개는 `(1000, 24)`로 바로 바꿀 수 없다. 다음 정책 중 최소 두 가지를 실제 코드로 시도하고 하나를 최종 선택한다.

- **중단:** 데이터가 완전하지 않으면 오류 메시지를 남기고 처리하지 않는다.
- **마지막 공간 제거:** 불완전한 마지막 공간의 17개 값까지 제거하고 `(999, 24)`로 처리한다.
- **부족한 7개 채우기:** 특별한 정수값 또는 `NaN`을 넣어 `(1000, 24)`로 처리한다.

`README.md`에는 각 정책이 버리는 정보 또는 새로 가정하는 값, 최종 정책, 그 정책이 부적절해질 수 있는 상황을 기록한다.
