# 거래 기록의 범주·월별 매출 요약

매장 담당자가 범주별 매출과 월별 변화를 확인할 수 있도록 거래 기록을 세 요약표로 변환한다. 입력·정리·집계·검산·저장이 연결되는 하나의 실습이다.

## 제공 입력과 실행 환경

제공할 파일은 `README.md`와 `sales.csv`다. 아래 CSV가 예제 데이터이며 한 행은 거래 한 건이다. 매출 단위는 천 원,  이 예제에는 기간 내 모든 거래가 수록됐다고 가정한다. CSV의 event_id는 강의 HTML에서 사용하는 행 인덱스 1–4에 대응한다. 읽을 때 이 열을 인덱스로 사용한다.

```csv
event_id,occurred_at,category,channel,sales
1,2026-01-03, Drink ,web,10
2,2026-01-10,drink,web,20
3,2026-02-01,DRINK,store,30
4,2026-02-14,Food,store,40
```

Python 3와 pandas를 사용한다. 강의 예제는 pandas 1.4.4에서 검증했다. 버전별 출력 공백이나 날짜 자료형의 단위 표기 대신 날짜·셀 값·결측 여부로 결과를 비교한다.

| 명령 | 목적과 읽는 대상 | 바뀌는 파일·확인 결과 |
|---|---|---|
| `python --version` | 실행기 버전 확인 | 파일 변경 없음, Python 버전 출력 |
| `python -c "import pandas as pd; print(pd.__version__)"` | 설치된 pandas 확인 | 파일 변경 없음, pandas 버전 출력 |
| `python build_sales_summary.py` | 현재 작업 폴더의 `sales.csv`를 읽어 요약 | `output/`의 CSV 세 개 생성 또는 덮어쓰기, 성공 문장 출력 |

`build_sales_summary.py`와 `sales.csv`가 있는 폴더에서 실행한다. AI로 코드 초안을 작성해도 되며 실행 결과가 아래 값과 일치하는지는 직접 확인한다.

## 처리 순서와 성공 기준

1. **입력 점검과 범주 정리:** 거래 4행, ID 고유성, 필수 열을 확인한다. `category`의 양끝 공백을 없애고 영문을 소문자로 바꾼다. 범주는 drink·food 두 개가 되어야 한다. 범주·날짜·매출의 결측은 성공으로 처리하지 않는다.
2. **범주 요약과 교차 요약:** `groupby`와 이름 붙은 집계로 거래 수·매출 합계·거래당 평균을 계산한다. 범주×판매 경로 피벗에는 합계 집계를 명시한다. 평균의 분모는 이 입력에서 결측 없는 거래 수다. 전체 거래가 수록됐으므로 거래가 없는 food×web 조합은 0으로 채운다.
3. **월별 시계열:** 날짜 문자열을 변환하고 시간 인덱스를 정렬한다. `resample("MS").sum()`으로 달마다 합계를 만들고, `shift(1)`로 직전 달 값, 차감으로 변화량, `rolling(2).mean()`으로 두 관측 이동 평균을 만든다.
4. **검산과 전달:** 아래 모든 범주·셀·월별 값과 총매출 100을 대조한 뒤 CSV 세 개를 저장한다. 첫 달의 이전 값·변화량·이동 평균은 비교 대상이 부족하므로 결측을 유지한다.

## 기대 출력

`output/category_summary.csv`의 행 기준은 범주다.

| category | event_count | total_sales | mean_sales |
|---|---:|---:|---:|
| drink | 3 | 60 | 20.0 |
| food | 1 | 40 | 40.0 |

강의의 n·total·avg 열을 전달용 CSV에서는 event_count·total_sales·mean_sales로 이름 붙인다. 값은 같다.

`output/channel_matrix.csv`의 한 셀은 범주와 판매 경로가 만나는 매출 합계다.

| category | store | web |
|---|---:|---:|
| drink | 30 | 30 |
| food | 40 | 0 |

`output/monthly.csv`의 행 기준은 각 월의 시작일이다. 아래 `결측`은 CSV에서는 빈 칸으로 저장해도 된다.

| occurred_at | sales | previous | change | rolling_2 |
|---|---:|---:|---:|---:|
| 2026-01-01 | 30 | 결측 | 결측 | 결측 |
| 2026-02-01 | 70 | 30 | 40 | 50.0 |

모든 검사를 통과하면 터미널에 `OK: 4 events; 2 categories; 2 months; total 100`을 출력한다. 합계 일치만으로는 범주별 값이 옳다고 할 수 없으므로 표의 셀도 비교한다. 이 세 CSV가 시각화 담당자에게 전달할 최종 산출물이며 그래프 작성 코드는 이 실습의 제출 대상에 포함하지 않는다.

## 제출 파일과 평가기준

제출물은 `build_sales_summary.py` 한 개와 생성한 `output/category_summary.csv`, `output/channel_matrix.csv`, `output/monthly.csv`다. 소스는 빈 줄·주석을 포함해 100줄 이내로 작성한다. 개인 이해도는 실습 종료 후 현장에서 확인하고 Discord 비공개 서술형 문항 한 개로 별도 평가한다.

| 평가기준 | 제출물의 직접 증거 |
|---|---|
| 제출한 Python 소스가 .py 파일 한 개이고 100줄 이내인가? | 소스 파일 개수와 실제 전체 줄 수 |
| 문자열·날짜 정리와 범주·경로·월별 집계가 정확한가? | 세 CSV의 범주·건수·네 교차 셀·월별 합계가 기대값과 일치 |
| 이전 값·변화량·이동 평균과 검산이 정확한가? | 월별 CSV의 값·첫 결측, 재실행 성공 문장, 셀·ID·합계 검사 코드 |

## 저장소 배치

학생 저장소의 `Week05/`에 안내문, `sales.csv`, 작성한 소스와 생성한 `output/`을 함께 commit하고 push한다. 제공 CSV도 같은 제출 commit에 포함한다. 서술형 퇴실 답변을 제출하면 개인 저장소의 push 권한이 회수되므로, 답변 전에 모든 제출물을 push한다. 다른 입력을 받으면 고정된 기대값 검사가 실패할 수 있으며, 이 실습의 검산값은 제공 데이터에 대한 값이다.
